# Experience first

When implementation convenience conflicts with a good user experience, choose the experience.

- Justify every feature, control, and option.
- Ship less and polish it. Three polished features beat ten rough ones.
- Prototype before committing. Design decisions are cheaper to make in throwaway HTML than in production code.
- Get the details right: transitions, alignment, spacing, feedback, error states.
- Tighten the core loop. Every feature should serve the central workflow or stay out of its way.

The user is whoever consumes the work. For a UI that's the end user; for a library or internal API it's the colleague who imports it. The engineer who maintains the code next is a user too. Weigh their experience the same way, and describe impact from their point of view.

[foundational-thinking](foundational-thinking.md) governs the order of work; this principle governs the target. Foundations exist to serve the experience.
